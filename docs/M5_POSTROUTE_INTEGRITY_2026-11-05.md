## How the missing report issue was resolved

The original placed `check_setup.rpt` files were empty, which meant we could not rely on those archived reports alone as evidence for constraint coverage. We explicitly **reopened the original routed physical design** in pinned OpenROAD and reread its `top.sdc` and extracted `routed.spef`. The Tcl invoked `check_setup -verbose` with begin/end markers and regenerated both target read and global setup reports. All 24 executions exited successfully. A separate verification workflow confirmed the exact number of rechecks and no detected setup warning/error strings.

**Important caution:** the successful `check_setup -verbose` commands were silent between their markers. The absence of a warning is a limited automated coverage check, **not** independent proof that every intended path in a production block is constrained. We deliberately do not assert signoff-grade constraint completeness. The verified existence of both registered path classes and the same whole-design ranking in 12 comparisons supports the narrow exploratory timing interpretation.

## Conclusions supported by M5

- The final synthesized RTL predictor dataset's **12/12 whole-design vs target-read preference agreement** means the 9/12 predictor accuracy and 11/12 blind-word accuracy are not artifacts of selecting an unrelated target path when the full-design setup winner is considered in those pairs.
- Row vs word choices within each pair used equivalent functional timing intent: write-time differences in serialized SDC are metadata comments, not altered setup/hold uncertainties, clock period, I/O delays or output load.
- Archived timing uses physically routed extracts reread through `read_spef`, not merely placement RC estimates.
- The scientific result remains **bounded**: correct architecture-ranking checks do not turn the exploratory flow into a PDK signoff methodology or a general predictor.
